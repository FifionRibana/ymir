# Viz-0 C1 Integration — Stage A Acceptance Checklist

Issue [#137](https://github.com/FifionRibana/ymir/issues/137) — manual visual + interactive checklist that **must be exercised by the user** before merging the Viz-0 PR. The headless acceptance test (`acceptance_full_run_seed_42_pangaea_collapse` in [bridge/c1/thread.rs](../../../crates/ymir-viz/src/bridge/c1/thread.rs)) validates the numerical outcome (Pangaea collapse 8 → 2 at seed 42 / 64²×300, matches Track D Stage A evidence), but the UI surface (sprite rendering, colour palettes, view-switch in pause, overlay toggles, engine selector) is not automatable in CI without a display.

This checklist documents every contract that was specified during the Viz-0 stage-by-stage workflow (Stages S → V) — each item has an explicit action and an observable success criterion.

## How to run

```bash
cargo run --release -p ymir-viz --features v2_legacy
```

The binary launches a Bevy/wgpu window titled "Ymir — Continent Generator (v2)" at 1280×720. The C1 engine is selected by default; the C1 control panel ("C1 Engine Controls") opens at the top-left.

## Checklist

### 1. Boot

- [ ] **`cargo run -p ymir-viz --features v2_legacy` opens the window.** No crash; primary window renders the background. C1 sprite (z=12) is the default visible engine.
- [ ] **The "C1 Engine Controls" egui window is visible.** Top-left position around (20, 80), width ~320 px. Five collapsing sections visible: Init parameters, Closures, (Run controls), Field, Overlays, Live stats.

### 2. First run

- [ ] **Press ▶ Run.** Default spec is `grid_size = 64`, `seed = 42`, `n_steps = 300`, all 7 closures enabled (including Track D).
- [ ] **Animation begins step-by-step.** The C1 sprite updates over ~250 ms (Track D Stage A measured 838.7 µs/step × 300 = ~252 ms). Sprite resizes from 1×1 placeholder to 64×64 at first frame.
- [ ] **No flickering or jitter on the v2 sprite below.** v2's sprite at z=10 is dark/black (V2RunState::Idle); C1 covers it via z=12.

### 3. Track D evolution visible (acceptance gate)

- [ ] **Live stats panel updates during the run.** Step counter shows `Step N/300`. Grid shows: `live plates`, `subduction cells`, `accretion merges`, `rifting splits`, `rifting cells thinned`.
- [ ] **`live plates` decreases from 8 to 2 over the run.** Pangaea collapse signature — accretion merges 6 plates by step 300 (matches headless test stat).
- [ ] **`subduction cells` is non-zero throughout the run.** High-frequency event.
- [ ] **`accretion merges` reaches ~6 by step 300.** Matches Stage A evidence.
- [ ] **`rifting splits` is 0 at seed 42** (expected per Stage V evidence: seed 42 has 0 splits; chewing-gum cut is rare).

### 4. Six field modes

After Run completes (or during a pause), use the **Field** dropdown:

- [ ] **S̃ (crustal thickness).** Hypsometric ramp on `[0, 3.0]`. Continental cells light blue → green / brown; oceanic dark blue. Matches Track A/B/D PNG galleries.
- [ ] **Age field.** Auto-normalised per-frame. Cells reset to 0 along ridges (Track B Path 3.A init) → teal; mature oceanic → olive / amber. Continental high age → red / brown.
- [ ] **Plate ID.** 12-color hash-mod hue palette. Distinct hues for the 8 init plates; same id renders identically frame-to-frame (no scintillation). Accretion merges visually swap a region to the winner's hue.
- [ ] **Plate type.** Cyan (oceanic) + beige (continental). Sharp boundary, no anti-aliasing.
- [ ] **Altitude.** Architecture C bipolar palette `[-1.13, +1.13]` sym; sea level at the blue→green transition. **Spot-check vs gallery PNG**: open `docs/reports/c1_phase_2_track_d_boundary_evolution/cycle_300_altitude.png` side-by-side — coastlines and continental shape should match (allowing for per-frame normalisation variance in the gallery).
- [ ] **Cratonic.** Binary grayscale 0/1. Black background with white patches at the cratonic-mask cells. NOT recomputed per step (one-cycle lag per Issue #132 Q-S.2).

### 5. View-switch during pause

- [ ] **After Run completes**, swap field via the dropdown.
- [ ] **The sprite re-renders instantly** (no channel round-trip). Tests the cached-snapshot contract from Stage E3 W4.

### 6. Altitude vs gallery spot-check

- [ ] **Open** `docs/reports/c1_phase_2_track_d_boundary_evolution/cycle_300_altitude.png` (generated by Track D Stage A; will exist after a `cargo test --release -p ymir-core --test c1_phase_2_track_d_visual_gallery -- --ignored --nocapture` run).
- [ ] **Compare the C1 live altitude view to the PNG.** Coastlines at the same positions, deep ocean at the same colour intensity, continental highs at the same locations. Track A/B/D galleries used the same Architecture C derivation + bipolar palette, so the C1 live view should match within rendering tolerance.

### 7. Overlays

- [ ] **Toggle "Voronoi boundaries"** (Overlays section). Black lines appear at plate-boundary cells. Cardinality-agnostic — accretion mergers cause boundaries to disappear (cells absorbed into the winner's region); rifting split would spawn new boundaries (rare at seed 42).
- [ ] **Toggle "Velocity arrows"**. White arrows per plate, anchored at the per-plate centroid. **Hover the checkbox** — tooltip surfaces the init-time limitation:
    > Init-time per-plate velocities only. Mid-run mutations from accretion / rifting splits NOT reflected (Viz-0-bis Option B follow-up).
- [ ] **Adjust the arrow scale slider** (0.5–20.0). Arrows grow/shrink linearly.

### 8. Closures run-locked

- [ ] **Press ▶ Run** to start a new run.
- [ ] **During Running**: open the Closures collapsing section. **All 7 checkboxes are grayed out** (disabled). Hint text visible: `(disabled during run; closures are run-locked)`.
- [ ] **After Completed**: checkboxes become editable again.

### 9. Init params dirty flow

- [ ] **In Idle / Completed**: change `grid_size` to 32 (DragValue), change `seed` to 1337.
- [ ] **Press ▶ Run.** Worker re-inits from the edited spec (no separate Init step — mirrors v2 pattern).
- [ ] **Live stats reflect the new run** (smaller grid, different seed pattern). 

### 10. Engine switcher

- [ ] **Click "v2 (legacy)"** in the Engine row at the top.
- [ ] **The C1 sprite disappears** (Visibility::Hidden on C1VizSprite); v2's sprite at z=10 is visible underneath (dark placeholder if v2 is Idle, or v2's last state if it ran). C1 panel sub-controls (init params, closures, etc.) gray out with the message "Switch to C1 engine to access these controls."
- [ ] **Run v2 if desired** (use v2's own control panel). v2 engine works unchanged.
- [ ] **Click "C1 (Track A/B/D)"**. C1 sprite reappears immediately. No crash. No artefacts.

### 11. Plate ID visual evidence of Track D

- [ ] **Field → Plate ID** during or after a 300-step run.
- [ ] **Observe**: at cycle 0 the grid shows 8 distinct hue regions. By cycle 300, only 1-2 distinct hues remain — accretion mergers visualised.

### 12. Cancel button (MVP Option C semantics)

- [ ] **Press ▶ Run.**
- [ ] **Press ■ Cancel during the run.** The cancel flag is set on the AtomicBool, BUT the current run continues to completion (Q-E1.3 MVP — no per-step cancel hook in `run_with_closures`).
- [ ] **After Completed**: the next ▶ Run press is blocked? Actually no — the worker checks the cancel flag *between* commands, and the test only cancels future runs implicitly via the flag. **Acceptable for MVP**: a Viz-0-bis follow-up will add `tectonics_c1::cancel` (~1 day) for true mid-run interruption.

## Worker pipeline — standalone `run_with_closures` (Issue #137 Stage A — A1-c reverted)

The viz worker calls **standalone `run_with_closures` with NO `apply_post_tectonic`**, mirroring the Track D visual gallery (`c1_phase_2_track_d_visual_gallery`). This is the deliberate reference path for what the viz reproduces.

### CAVEAT FRANC — coast is static in the displayed path, not in C1

In the standalone path (closures without post-tectonic), the visible coastline is quasi-static **because the land/sea boundary is carried by `plate_type`, which the workflow's post-tectonic re-derives end-of-cycle, but the standalone path does not.**

This is **NOT** "C1 produces static coasts". The full C1 Phase A pipeline (workflow) re-derives `plate_type` via `apply_post_tectonic` reclassification at end-of-cycle, and **would** migrate the coast.

**Viz-0 MVP reproduces the gallery path, not the workflow path.** The static coast is a property of the **displayed path**, not of the C1 model itself.

Why the gallery path and not the workflow path:

1. The Track A/B/D `*_visual_gallery.rs` PNGs at `docs/reports/c1_phase_2_*/cycle_*.png` are produced by standalone `run_with_closures`. The viz reproduces them as ground-truth reference.
2. An attempted "workflow per cycle" worker variant (A1-c, commit `a2f5eec`) ran `apply_post_tectonic` 6× per default run with `steps_per_cycle = 50`. `macro_redistribution` is calibrated for **ONE** pass per cycle in Phase 1.x workflow tests (single 300-step cycle). 6× the calibrated cadence over-eroded the continent → near-zero continental fraction at cycle 300. Reverted.
3. The workflow path with **proper multi-cycle macro_redistribution calibration** is a Viz-0-bis follow-up requiring a Phase 1.5 calibration study (see §"Viz-0-bis backlog" below).

### Mechanism — why `plate_type` carries the visible coast

`compute_isostasy` ([isostasy.rs:69-88](../../../crates/ymir-core/src/tectonics/isostasy.rs#L69-L88)) is purely S̃-based; the sea-level threshold `h_sea = h_min + sea_level_fraction × h_range` floats with global S̃ extremes. `apply_stein_stein_bathymetry` ([source_term.rs:163](../../../crates/ymir-core/src/tectonics_c1/closures/oceanic_bathymetry/source_term.rs#L163)) overwrites altitude **only** for `plate_type == Oceanic` cells; continental cells retain their isostatic altitude.

The visible coast (altitude=0 line in Altitude view) emerges at the **plate_type boundary** as a discontinuity — Oceanic side has S-S depth-from-age (strong negative), Continental side has isostatic altitude (positive). When `plate_type` is static (gallery path), this discontinuity does not move and the visible coast does not migrate.

A continental cell whose S̃ drops via erosion / advection below the floating `h_sea` would, in principle, cross to visible-ocean without reclassification. In practice this mechanism does not trigger visibly under default closures over 300 steps — the dynamic range of continental S̃ evolution is insufficient to push cells across the floating threshold (test 4 verdict).

### Static fields (gallery contract)

- **plate_type** — set at init by `init_c1_state_phase_2_r7`, never mutated by `run_with_closures`. Static across the run.
- **cratonic_mask** — set at init by the BFS-from-continental-seeds pass, never recomputed. Static across the run.
- **Continental fraction** — preserved across the run (gallery contract, verified by test 4).

### Architectural findings (Stage A)

1. **Coast migration in C1 requires reclassify**. The standalone gallery path produces visually-static coast despite live S̃ dynamics. The full Phase A workflow re-derives `plate_type` via `apply_post_tectonic` end-of-cycle, and that is what migrates the visible coast. Property of the **displayed path**, not the C1 model. Viz-0-bis "workflow mode" toggle is the path to dynamic reclassify in the viz.
2. **A1-c failure mode** (commit `a2f5eec`, reverted): multi-cycle `apply_post_tectonic` at `steps_per_cycle = 50` ran `macro_redistribution` **6× the Phase 1.x calibrated cadence** (Phase 1.x = 1 cycle = 1 macro per run). Over-erosion collapsed the continent to near-zero fraction by step 300. PlateType view also showed rendering artefacts (white panels at later cycles) likely from the per-cycle `plate_type` mutation pattern. A correct workflow-mode toggle requires Phase 1.5 calibration for multi-cycle use.
3. **`plate_type` + `cratonic_mask` are init-only in C1** (gallery contract). Neither is recomputed inside `run_with_closures`. Only the full `apply_post_tectonic` pass (workflow) mutates `plate_type` via reclassification; only `apply_post_tectonic` step 4 (gated by `initial_per_plate_type` + `cratonic_cfg`) recomputes the cratonic factor (not the BoolField mask).
